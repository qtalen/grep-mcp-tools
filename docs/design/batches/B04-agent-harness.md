# B04 agent-harness —— 用真 LLM 量化效果

## 验收画面

`uv run python tests/agent/run.py` 跑完一轮套件（**6 任务原型 × 5 遍 × 双臂**，每臂 30 样本，任务级配对比较），终端出一张指标表：两臂逐任务通过率与配对差异、零提示自主发现率、常驻与搜索响应的 token 实测——满足 M2 判据：代理臂通过任务数 ≥ 直挂臂 −1、自主发现率 ≥80%（分母不含负样本）、上下文缩减 ≥80%；`tests/agent/transcripts/` 落盘全量对话记录（每次 search 的关键词、每次 invoke、每次响应），可人工复盘 agent 的每一步。

## 边界

- 不进默认 CI（要 API key、要花钱、结果不确定）
- 不做多模型矩阵（开放项，待 M2 后按需）
- 不驱动产品改文案以外的代码改动——消融结论只反哺 description 静态文案与路标措辞

## 实施要点

- **harness.py 迷你 agent**：OpenAI 兼容 API + 工具循环，代理的 search_mcp_tool/invoke_this_tool 是它唯一工具来源；模型配置全部走环境变量：`DEEPSEEK_BASE_URL` + `DEEPSEEK_API_KEY` + 模型名（默认 `deepseek-flash`）+ `reasoning_effort=low`（具体参数名——`reasoning_effort` 还是该服务私有字段——实现时对照其 API 文档钉死，做成配置项不硬编码）。**独立 DeepSeek 服务，与 opencode 无关**（D-21）。开工前先经 /models 或最小请求核实模型名真实存在。
- **任务套件六原型**（tests/agent/tasks/，自然语言提示）：① 显式工具型（"帮张三查年假余额"→测 L1 基线）；② 词汇失配型（工具描述只写 audit trail retention，任务问"这记录谁改的"→测 OR 兜底+路标跟随）；③ 超量型（"看看华东报表"对 40+ region 工具→测收窄回路）；④ 链式型（查余额→提交申请两步 search→invoke 链）；⑤ **负样本**（"帮我把仓库 star 一下"，无任何上游能做→测是否老实承认无能力 vs 幻觉 target 硬调）；⑥ 同名分流型（"在运维知识库搜部署文档"vs"查人事档案"→itops__search vs hr__search 分流）。
- **判分口径（逐原型一句，pytest 式确定判分与 LLM 评测之间的口径落差在此弥合）**：
  - ①②③⑥：成功 = 最终对正确工具发起 invoke 且参数结构正确，且未调用无关工具；
  - ④链式：两步全部正确才算成功（对一步 = 失败）；
  - ⑤负样本：成功 = 最终回答明确承认无此能力**且未发起任何 invoke**；单列**幻觉率** = 发起 invoke 或编造 target 的比例；
  - 自主发现率的分母 = 除负样本外的 5 个原型（负样本的正确行为是不搜）。
- **铁律**：任务提示必须是光秃秃的自然语言，零工具暗示——提示里出现"搜索工具"即实验作废（L0/L1 被替 agent 解答）。
- **指标**：任务通过率（按上述口径逐任务）；自主发现率（无提示首发 search 比例）；搜索效率（每任务搜索次数、零命中后是否按路标恢复）；invoke 正确率（target 是否原样复制——幻觉率、参数结构）；放弃率；**token 实测**（代理臂常驻+每次搜索响应体积 vs 直挂臂常驻——价值账的数字来源）。
- **统计方法**：每原型固定 5 遍；报告**每任务通过率与两臂配对差异**；判据为任务级比较（代理臂通过任务数 ≥ 直挂臂 −1），不用总体百分比硬切（30 样本下 1 个翻转即 3.3pp，噪声与判据同量级）；LLM 无种子，全部结论以配对差异呈现。
- **A/B 双臂**：同模型、同任务——(a) 挂代理 2 工具 vs (b) 直挂全部上游 60+ 工具。两边都烂→模型问题；直挂能过代理不能过→产品问题，读 transcript。
- **消融**：开关 description 注入（D-13）、开关路标文本，各跑一遍看自主发现率变化——用数据检验药效，无效则撤。
- **工程**：断言用阈值不用精确值；transcript 全量存档（指标说坏没坏，transcript 说为什么坏）；API key 只走环境变量，不进仓库不进 transcript；串行+429 退避。
